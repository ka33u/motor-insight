# 联立试排策略对照

从“物料、人机联立试排”点击“并排比较两种派序”，或打开 `#joint-schedule?view=compare`。管理员、分析师、运营可查看，其他岗位沿用原联立试排的限制。

这页回答：同一份物料、设备、人员、BOM和时间范围下，改变派序会让哪些批次更早、哪些更晚、哪些仍未排完？两列独立调用原有算法，没有新增优化器、改变物料假设或批准计划。

## 先确认两列能比较

左列固定为“应完成时间优先”，右列固定为“批次优先级优先”。同一数据库读取事务内取得两种试排，核对来源、原规则、物料/人员/设备输入、方案版本和完整对象身份一致。对象按编号配对，不能按显示顺序或相似名称匹配。

任一列资料暂停时，两列保留各自状态、问题及原始输入，整个差异分析暂停。未计算不能显示为零需求、零延误或零变化。

## 页面阅读方式

1. 核对共同方案、假设版本及时间范围。两列卡片都保留完整批次、未排批次、晚交和已排任务的原始分母。
2. 看三态转换矩阵和全部批次表。每个批次只归入一个“按假设已排／晚于交期／未排入”组合；两列台数不相加。
3. 看批次完成时间及晚交分钟差异。仅当两列均完整排入，才计算时间差；新获得或失去完整安排另列，两列均未排完也单列。
4. 在任务清单查看设备、人员、开始/完成与首个阻断任务。可按批次、是否发生变化分页筛选，点击任务并列核对整批需求、预留及实际触发份号。
5. 在物料清单核对同物料同单位的预留与剩余差异，再看需求编号＋供给编号配对的预留流水。数量相同但触发时间、任务或供给份额不同，也属于预留变化。

所有差值统一为**右列减左列**。完成时间负值表示右列更早，正值表示更晚。已完整排入但晚交，仍须保留晚交状态；“更早”不等于“按期”。共同等待与物料就绪等待的原有边界继续适用，不能相加。

物料的预留差值＋剩余差值必须等于0。不同物料、kg和件分别显示，不计算混合总量。某列没有一笔预留时，其预留量明确为0，但预留时点仍为空；未排任务的时间不以0替代。

下列均来自已导入的第39份模拟Excel，属于独立假设，不能合并为实际库存或产量：

|---|---|
| MP-261002-001 完整共享供给 | 6批次均排完，右列3批更早、3批更晚 |
| MP-261002-003 次日下午到料 | 两列均排完；晚交从6批变为3批，但仍有3批完成时间更晚 |
| MP-261002-004 期初与未来拆批 | 6批次均排完，右列5批更早、1批更晚 |

## 来源、返回与导出

共同来源覆盖全部共享物料、人机和BOM依据，可分页到Excel表和行。“查看该策略的完整试排”带入该列凭据；资料、规则或账号变化后必须重新读取，不能静默跳到一套新结果。

清单局部筛选只改变该清单，上方整案汇总、共同来源以及标明的“完整两列”导出保持全方案范围。CSV/JSON包括全部差异、两列完整结果、原始假设、最小必要档案字段及来源。暂停方案也保留全部输入。导出不包含活动凭据、价格或工时成本字段；成功导出留审计，读取不写业务记录。

接口为 `POST /api/joint-comparison/<方案编号>`，另有 `/sources`、`/tasks/<任务编号>`、`/export`。条件和凭据放在JSON正文，要求登录及CSRF。读取凭据有效期10分钟，绑定当前账号、来源、规则及两列结果；修改参数、旧凭据或无权账号不能复用。

## 验证边界

24项新增规则及接口用例核对差值方向、空时间、配对范围、物料守恒、权限、凭据、来源、暂停与导出回滚。11组纯JavaScript检查核对表格、转义、分页、策略返回及异步旧响应。隔离的公开Excel回放库通过六岗位原生HTTP演练：三岗位各读取10方案，两列与20种原算法结果一致，完整核对2,030条共同来源，9次完整/暂停导出。

当前没有新增业务输入或数据库迁移，沿用42份有效Excel和154个原始数据定义。主库数据、原件和原算法保持一致。真实岗位、浏览器、手机、键盘及实际下载操作仍未验收；订单冻结BOM驱动试排、更多约束及正式计划批准继续按原目录推进。
