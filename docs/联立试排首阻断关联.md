# 联立试排首阻断关联

0.25.0 为计划人员增加“首阻断关联”队列，先定位应核查的任务，再查看原候选设备、人员、窗口、缺料与Excel来源。入口仍是物料、人机联立试排的“排程与阻断”页。

## 页面与口径

队列从完整试排结果读取 `root_tasks`，按原首阻断任务号分组，不重算依赖、现场根因、关键路径或派工优先级。每行保留原编号、工序、分支和未排原因。

| 展示内容 | 定义与阅读限制 |
|---|---|
| 关联未排任务 | 本次方案中原首阻断列表含该完整编号的未排任务；含阻断点自身 |
| 涉及批次 | 上述任务对应的不同批次号，按编号去重 |
| 涉及批次台数 | 上述每批次的台数只取一次；不逐工序、份号累加，不代表损失产量或客户逾期量 |
| 多首阻断任务 | 同时关联两个以上首阻断的任务，提醒同一任务可能出现在多行 |
| 完整方案摘要 | 对全方案所有未排任务、涉及批次分别去重；不能累加队列各行得到 |
| 最早内部应完成 | 行内关联批次的最小内部目标时间；是厂内假设时间，不是客户承诺或实时逾期判断 |
| 阅读顺序 | 最早内部目标升序、批次数降序、任务数降序、原编号升序；仅用于查阅 |

资料暂停不显示零阻断。编号缺失或重复、关系不完整、批次台数/内部时间无效、状态与完整摘要不一致时暂停关联计算；原任务、资料问题和全方案来源仍可核查。本版不建立新指标版本，不改变已发布指标或排程计算。

## 点击与范围

- 点首阻断任务号，用当前方案、策略和签名凭据打开原任务详情，可继续沿前序和首阻断读取候选人机及来源。
- 点“查看 N 项任务”，清除原批次选择并选中未排状态，显示该首阻断的全部关联任务。
- 批次、状态和首阻断条件取交集。“重置明细选择”恢复全部任务。零匹配明确提示，不代表整个方案没有阻断。
- 队列每页40个首阻断；摘要和任务筛选使用完整结果。两个阅读页之间保留选择和设备/人员轴；重新读取、更换方案或策略后重置。
- 顶部汇总、首阻断队列、甘特图、全部来源及完整CSV/JSON均保持全方案范围。任务筛选不会生成局部导出；JSON的 `result` 可用同版 `jointBlockerReport` 复原队列。

管理员、分析、计划岗位沿用既有联立权限，来源索引仍不授予原件下载权。没有新增API、业务输入、Excel、迁移、模型发布、预留释放或正式批准。

## 可核对的模拟例子

| 方案（内部目标优先） | 首阻断数 | 去重未排任务 | 涉及批次 / 台数 | 多首阻断任务 |
|---|---:|---:|---:|---:|
| MP-261002-005 | 2 | 32 | 1 / 8 | 24 |
| MP-261002-006 | 12 | 198 | 6 / 50 | 150 |

005的两行各关联28项任务、8台，直接相加会得到错误的56项/16台；实际去重为32项/8台。006各行合计348项/100台，完整去重为198项/50台。行内关联量并非可加指标。

## 验证与边界

21组新增纯JS检查包括手算交叠例子、真实模拟方案、去重、日期与数量缺失、摘要截断、排序、分页、转义、明细交集、重置、页间保持、重读清除及异步详情竞争；同时复跑112组相关纯JS。2,770项完整后端回归通过。

在0.19.0公开Excel正常回放库的隔离副本，通过原生HTTP验证六岗位；三种获准岗位各读取10个方案×两策略，核对005/006共28份首阻断和关联任务详情、006全部2,014条来源及3份完整导出。60个HTTP方案结果和6份JSON导出结果由独立Python集合计数与当前JS函数交叉核对。005来源数为2,030，006为2,014，按各方案真实返回范围核对，不能套用固定总数。

主库232,200条事实、原计算器、初始化Excel及458份原件保持不变；本版沿用公开回放副本，没有重做整库Excel初始化。BI目录仍为382项候选需求，其中121项模拟部分覆盖、261项待建设。浏览器布局、手机、键盘、实际下载和真实工厂使用仍未验收。
