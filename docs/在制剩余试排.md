# 在制剩余试排

版本 0.37.0 的 `#wip-trial` 使用正常导入的合成 Excel，对明确映射的完整工单计算剩余任务。输入是带来源的模拟声明，不是从累计良品数、净领料或在制箱数猜测出来的进度。

## 读什么，做什么

| 顺序 | 页面内容 | 要回答的问题 |
|---|---|---|
| 1 | 方案系列、版本、前版、截止和派序策略 | 当前查看哪套完整假设？历史版保留，最高版有错不会退回旧版冒充当前结果。 |
| 2 | 资料暂停原因，或四类任务计数 | 依据是否足以计算？历史完成、原人机续作、新排剩余和未排任务互斥。 |
| 3 | 工单覆盖及交期 | 每张完整工单能否排完？有任一阻断就不填完成时间，也不计准时。 |
| 4 | 设备与人员两个未来时间轴 | 哪些原人机被续作占用？其余任务在哪个连续窗口安排？ |
| 5 | 任务清单与原报工明细 | 完成数、剩余数、剩余分钟和中断恢复分别来自哪里？ |
| 6 | 余料与预留 | 尚需投入多少？哪些已投入在制品，哪些仍是共享或专属库存？ |
| 7 | 原 Excel 来源及完整 CSV/JSON | 文件、工作表、行、记录版本和摘要能否复核？能否离线重算同一结果？ |

明细可按批次和四类结果取交集；只筛任务表，不改变全方案汇总、时间轴、来源或完整导出。甘特条和清单任务可进入同一明细。方案暂停时不显示零负载、零缺料或零延期。

## 为什么选这组人机

任务明细按原输入的每个资源候选×人员候选列出完整比较。批量核对对加工中使用原处理量，对未开始和中断待续使用剩余量；加工中限定原人机并从截止连续续作，准备为零。其他任务准备包括首次/跨族换型与声明的恢复分钟。

解释取得的是**轮到此任务、尚未预留前**的共享状态：前序及材料就绪时点、设备和人员尾部、尾部对应任务、上个换型族和余料余额。候选窗口取设备日历、人员日历与资格有效期交集，再避开人机不可用时段，并满足保守尾部限制。时间区间右端不含；不能回填更早空档。

| 情况 | 明细含义 |
|---|---|
| 本次选中 | 与原试排的人机、时点、准备分钟一致 |
| 可行，排序未选中 | 本轮有连续窗口，但按明确排序靠后；不代表替换建议或全局最优 |
| 批量 / 资格 / 锁定不符合 | 保留原候选并列出排除原因 |
| 前序阻断 / 缺料 | 未尝试连续窗口，不据此声称无产能 |
| 尾部后无连续窗口 | 当时已排占用、资格、日历和不可用时段共同限制下未找到窗口 |
| 历史完成 | 保留原报工，不生成未来人机候选 |
| 解释不可用 | 超过1000组合或200000窗口核对工作量，或重算不一致；不截取部分候选，原排程仍保留 |

未开始/待续任务按完成时点、开始时点、资源编号、人员编号、资源候选编号、人员候选编号、资格编号及准备秒数依次升序选首项。加工中已经固定原人机和时段，只按资源候选、人员候选、资格编号升序。完整排序值可展开查看。

可以沿同一凭据点击直接前序、首个阻断及尾部占用任务。相关余料显示此任务前余额；下面的余料表仍是全方案最终余额，二者不混加。未来供给不代表截止已在库。首阻断队列及筛选见下节；算法阻断关系不等于现场根因。

任务 JSON/CSV 同时含本任务解释和**完整方案**的输入、父方案、结果及来源，以保留人机和共享物料竞争。JSON沿用完整方案格式，并增加 `task_id`、`decision`；可用 `app.wip_trial_replay.replay_decision(document)` 重算解释。独立定义版本为 `WIP_DISPATCH_EVIDENCE_1`，回执也绑定解释定义摘要，十分钟失效规则沿用。

0.37.0 沿用47份有效初始化Excel，没有增加业务事实、输入表或数据库迁移；235,614条事实、476个归档路径、28份原联立及16份在制结果均保持。解释为可选观察副本，不改变派序选择或共享池。

## 从首阻断队列进入明细

当前阅读定义只支持 `WIP_REMAINDER_SHARED_POOLS_1`、两种既有策略及明确方案版本；未知算法版本不沿用旧口径。队列按完整任务前序图核对每个 `root_tasks` 关系。后序应继承所有未排前序的首阻断集合；没有未排前序但自身未排入时才形成新首阻断。资料缺失、重复、环路、跨工单依赖、错误传播、四类计数或工单完成时点不一致时，队列显示“未计算”，不把缺失记为零。受控范围为最多5000任务，前序关系和根关联各200000条，超过时不截断。

| 阅读量 | 粒度、去重与边界 |
|---|---|
| 首阻断数 | 当前完整方案版本×策略内，不同原始阻断任务数 |
| 关联未排任务数 | 每个首阻断对应的全部未排后序及自身；全方案摘要按任务编号去重 |
| 涉及工单数 | 任务归属批次与原工单完整一一映射，按原工单去重 |
| 涉及整单台数 | 每张受影响工单的原完整数量只计一次；不是剩余量、损失量、真实延期量或恢复收益 |
| 多首阻断任务数 | 同一任务有多个原始阻断点，表示各行影响范围交叠；不能跨行相加 |
| 最早假设交期 | 关联工单原试排目标日期的最小值，不混用实际完成日期，也不是新的交付承诺 |

48号输入的003专属余料案例中，两个首阻断各关联22项任务，共44次关联；其中18项重叠，去重后为26个未排任务、1张工单及整单6台。不能把44解释为未排任务总数，也不能把两行各6台相加成12台影响量。

队列顺序依次按最早假设交期、涉及工单数、关联任务数和编号。每页20条，但摘要始终是完整方案。点击数量重置工单/状态并聚焦全部关联任务；随后工单、四类状态、首阻断取交集，重置返回完整清单。点击首阻断任务进入同版、同策略和同来源凭据的明细；切换筛选后旧明细请求失效。

筛选只影响任务表，全方案汇总、甘特、来源及完整CSV/JSON导出范围不变。完整导出包含完整任务图、原根关系和工单映射；展示聚合可由这些原始结果重建。任务表旁另提供当前交集的筛选导出，见下节。解除一个首阻断不保证其全部关联任务可排入，仍须重新计算完整共享物料与人机约束。

## 五张输入表

- `wip_trial_studies`：系列、版本、前版、原联立方案、截止、各表完整行数、内容与原始依据摘要。
- `wip_trial_jobs`：原试排批次与整个原工单一一映射，配置、路线、BOM及台数核对。
- `wip_trial_tasks`：每项任务必须有唯一进度声明；已开始任务明确绑定原报工。
- `wip_trial_materials`：每项任务与适用 BOM 绑定均有声明，包括零需求。已投入量指已经进入**剩余在制品**的材料。
- `wip_trial_supplies`：尚未耗用的余料假设，按物料×批次×位置唯一；线边盘点明确专属批次，仓库及未来到料共享。

正常 Excel 导入负责字段类型、必填、原引用和基本范围校验；跨表数量、完整版本、签名、前后序、报工与物料关系由试排核对。案例中的跨表矛盾会被保留用于演练，试排如实暂停。

## 时间、数量与材料

原任务数量 = 已完成数量 + 剩余处理数量。不同工序数量不能相加为整机产量。定子与转子在制份额也不能相加为台数。

已完成任务只提供实际完成时点及后序等待，不再占未来设备、人员或材料。加工中任务从进度截止原地续作；试排起点必须等于截止，保留原人机，资格和人机连续窗口覆盖全部剩余分钟。任一续作无法安置，整个方案暂停，不返回部分锁定或部分预留。中断待续重新参与派序，准备时间包含常规换型及明确声明的恢复分钟。

每条任务用料先按 `剩余数量 × BOM单耗 × (1 + 损耗率)` 向上取到规定步长，再减声明已投入量。整件必须为整数。已投入量不能超过剩余定额，不作为库存再次使用。**逐任务取整可能不同于原整批取整**，因此只保留原整批参考，不展示“节省材料”等因果差值。

余料池与原整批方案供给完全独立。先用本工单专属线边余料，再按可用时点和编号使用共享供给；他单专属不能借用。任务准备开始时一次预留剩余需求，物料可用时间不能晚于预留。隔离池可用量为零，其他池扣除明确不可投入量。逐批保持 `可用量 = 已预留 + 未预留`，失败后序不自动释放已排前序的预留。

算法沿用有限资源、人机、物料原方案的输入校验，新增独立剩余排程计算。设备和人员容量均为 1，一人全程陪同准备与加工，连续窗口、保守尾部追加、不抢占或回填。原先发布的整批联立计算没有替换。

## 模拟演练

48号工作簿有29张业务表及说明，共1,577行。新增2张同配置工单，各6台、各26个任务，4笔报工及4个分支在制基准。假设截止为2026-10-01 18:00，未来日历到10月5日18:00。

| 方案后缀 | 案例 | 两种策略下的预期 |
|---|---|---|
| 001 | 完整共享余料，完成前序、加工中及中断续作 | 历史完成2、原人机续作1、新排49、阻断0；覆盖2单 |
| 002 | 绕线相关材料不足 | 历史完成2、续作1、新排9、阻断40；覆盖0单 |
| 003 | 所有余料专属工单1 | 历史完成2、续作1、新排23、阻断26；覆盖1单 |
| 004 | 加工中声明剩余150分钟，连续窗口只有120分钟 | 整体暂停 |
| 005 | 完成数量与原报工不一致 | 整体暂停 |
| 006 | 001的v2，把续作12分钟更新为18分钟 | 保留v1，v2重新计算；覆盖2单 |
| 007 | 原始依据摘要不一致 | 整体暂停 |
| 008 | 声明已投入量超过剩余定额 | 整体暂停 |

这些案例因两单交期相同且优先级同序，两个策略结果相同；不能据此得出策略优劣。单元测试另覆盖竞争顺序、未来材料、原人机冲突及缺少完整映射等边界。

## 来源、权限与验证边界

管理员、经营分析师和生产计划员可读，其他三岗位无权限；原始五张表保持同一限制。导出不含成本、工资或人员姓名，记录成功导出的文件摘要。十分钟回执绑定来源、规则、策略、版本及账号状态；变化后须重新读取。JSON包含完整父方案输入、非财务参考、版本历史及来源，可用 `app.wip_trial_replay.replay(document)` 重算。

新增原始表由通用记录服务承载，无新增数据库迁移。公开初始化仅含正常导入的模拟Excel和原有安全分析配置；本地映射模板经原API复核为v13，保留v1至v12载荷，不把账号、会话或私有模板库打包公开。

规则测试、原生HTTP和公开空库回放证明的是当前模拟输入下的计算与访问行为。浏览器布局、手机、键盘和真实下载操作仍未验收。报废补产、返工路线、替代料、工装、多人协作、多机看护、历史资格存证、实际物料盘点及正式计划批准仍需后续建设。


## 当前交集的交付与复算

定义 `WIP_TASK_SELECTION_1`：一个完整方案版本、策略，以及工单批次、四类任务状态、原首阻断的交集。每个原任务只出现一行，顺序保持原派序结果；一个任务关联多个首阻断时，保留完整集合。筛选没有重新分配物料、人机、工单数量或完成时间。

- **筛选任务 CSV**：保留条件、当前/完整任务数、版本和摘要，逐任务原结果、对应原工单映射、整单原结果、任务进度声明及完整方案来源。该文件用于交接清单；来源索引不能替代完整输入复算。
- **筛选与完整依据 JSON**：包含同一清单，以及所有参与共享物料和人机竞争的原始输入与完整结果；`replay_selection` 先重算全方案，再校验交集、定义及摘要。不能删除未选任务后将文件当成独立排程。
- **空交集**：合法筛选无匹配时输出零条任务，保留条件与全方案任务数；暂停方案、未知工单/首阻断或失效凭据拒绝导出，不能解释为零风险。

整单台数及完成时间明确标为原工单完整结果，不按选中的工序折算产量。导出凭据绑定账号、来源、派序与筛选定义；成功响应按实际文件字节摘要审计。管理员、分析员和生产岗位可用，其余三岗位受限；不带工资、人员姓名或物料价格。

切换筛选、重置、切换内容页或重新读取会丢弃未完成的筛选文件响应；后发下载优先。页面通过服务端声明的能力版本决定是否显示新增按钮，旧服务仍可读取原报工和用料，显示完整导出的替代入口。浏览器布局、手机、键盘和实际下载未验收，现有界面检查是纯JS模拟交互。
