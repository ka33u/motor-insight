# 跨批次共享物料模拟

0.27.0 增加一份可正常导入的合成 Excel，展示多个批次竞争同一物料池时，派序如何改变获配批次。使用原有试排、策略对照、任务依据和逐物料 BI 页面，没有新增计算规则。

## 从哪里看

启动平台后，以演示管理员、分析或计划岗位进入“物料人机联立试排”，选择“**双批次共享硅钢·仅够一批**”（MP-261009-001），再打开“两种派序对照”。也可直接进入 `#joint-schedule?study=MP-261009-001`。

先核对两个批次的排完/未排状态，再回到单策略的“物料与预留”，点击 **01.01.0002**。逐物料页面显示两个批次的用量、整批需求、共享供给、原序预留和任务链接；可以继续查候选人机与 Excel 行来源。供给充足的对照案例为 MP-261009-002。

## 输入与口径

| 输入 | 声明假设 |
|---|---|
| 产品 | 原合成配置 CP.00008.A，保留当前 BOM、路线、物料和人机编号 |
| 批次 | SP-261009-001-B001 / B002，各6台，共12台；每批26个任务 |
| 内部交期 | B001：2026-10-10 18:00；B002：2026-10-11 18:00 |
| 优先级 | B001为2，B002为1；1优先 |
| 可试排时间 | 2026-10-09 08:00 至 2026-10-12 18:00，原合成日历顺延7天 |
| 人机 | 两批共用原设备与候选人员；一名操作员覆盖换型和加工，不增加并行容量 |
| 每批硅钢 | 定子55.704 kg + 转子29.995 kg = 85.699 kg；两批共171.398 kg |
| 需求取整 | 每条BOM按“批量×单耗×(1+损耗)”计算，kg向上取整至0.001，件向上取整至1 |
| 受限供给 | MP-261009-001共享85.699 kg，仅够完整一个批次；其余物料足量 |
| 充足对照 | MP-261009-002共享171.398 kg；人机、任务、交期及需求保持相同 |

两案例引用同一人机方案，但各自拥有独立物料供给假设。不能合并两个案例的供给，也不能把同一路线的多个任务份号重复计为整批用料。工作簿输入数量均为显式假设，非实际库存或领料。

## 正常导入和版本

`44_跨批次共享物料试排_模拟.xlsx` 含导入说明及16张标准业务表，共741行：资源方案1、批次2、任务52、依赖60、候选资源104、资源窗口160、不可用段4；人员方案1、资格20、候选104、人员窗口160、不可用段1；物料方案2、绑定18、需求36、供给16。

新方案、批次、任务、候选和供给使用独立编号，声明版本分别为 SHARED-BATCH-V1、SHARED-CREW-V1、SHARED-MATERIAL-V1。旧 Excel、旧方案和旧编号保留；没有绑定历史订单或将模拟批次冒充已批准工单。

首次安装按 `demo/workbook_manifest.json` 经正常预览、引用检查和提交导入43份有效工作簿，保留44份原始演示工作簿；最后导入本文件。已有0.26.0数据库可通过平台导入此文件，预览应为741行有效、无冲突、无未知表，再正常提交。重复导入同文件沿用原批次，不生成重复业务记录。

仓库的场景生成脚本只读既有合成事实，JSON仅作为制作Excel的中间文件；公开初始化只使用工作簿和安全分析配置。重新生成得到不同文件摘要时须重新核验，不应盲目覆盖已发布输入。

## 验证与范围

逐值检查全部741行和单元格类型，渲染核查17个工作表；从待公开文件空库正常回放，确认232,200条旧事实摘要保持一致，总计232,941条。四组计算独立核对72条BOM需求和32组物料账，检查设备及人员无重叠占用；再经六岗位本地HTTP核查两策略、物料明细、任务来源、受控导出与离线复原。完整回归及运行数量见 `demo/validation.json`。

原试排算法和已发布指标不变，仍不含抢占、自动释放、替代料、单位换算、模具或正式业务批准。浏览器布局、手机、键盘操作及实际浏览器下载仍未验收。真实U8/MES未连接。
