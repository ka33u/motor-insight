# 试排任务与资源依据阅读

0.23.0 修复资源、人机、物料联立、两种派序对照四页的面板正文参数错位。原表格和甘特图重新进入正文，保留原三参数面板语义，不改业务算法。

## 阅读顺序与范围

- `#finite-schedule`：完整批次交期、资源窗口与甘特、全部工序与阻断、资源负载。点任务可核查批内份号、换型族、前序和资源窗口。
- `#crew-schedule`：同一排程按设备或工号阅读，核查资格及两侧窗口、批次参考差值、人员占用。人员视角的纵轴明确为操作工号。
- `#joint-schedule`：在上述约束上加入整批用料、供给时间与预留。任务清单可按批次/状态阅读，标签保留当前数/完整数；顶部汇总、全方案甘特、全方案来源和完整导出不随此处选择改变。
- `#joint-schedule?view=compare`：完整两策略结果、三态转换、批次、任务和预留对照；两列共同来源和导出范围沿用原契约。

三种试排的任务依据不再展示原始JSON，而按身份与阻断、时点与占用、选中资源及资格、直接Excel来源分表。物料联立追加BOM版本、单耗/损耗/步长、单位、整批需求、已预留量、实际触发任务和供给批次。只展示接口返回的直接关系，不猜测现场领料、批准或完成。

## 指标与缺失边界

任务处理台数不能跨工序累加成批次产量；同一工序的不同份号可共用一次整批预留。页面同时列实际预留触发任务及本任务新增预留需求号，避免把相关预留当成本任务再次领料。

准备开始、加工开始、完成与物料可用分别列示；假设加工分钟不表示实际耗时。无完成时点、未排入及资料暂停不补零，数值0等待保留。不同物料/单位不合计；物料就绪、共同等待及同资源状态人员新增等待不能相加，也不代表现场停工、个人效率或因果损失。

任务详情只含直接来源；其他批次共享资源、人员和供给的竞争，需另读全方案来源与完整导出。原件读取仍按已有权限判断。

## 交互与验证

重新读取会移除旧凭据。四页共用请求失效规则：新读取、离开页面、关闭/替换弹窗或后发来源/详情请求使旧响应失效；失效请求的错误不覆盖当前操作。三种单策略导出加入防重复点击，与原有完整两策略导出保持一致。

38组纯JS数据、HTML字符串及异步状态检查使用正常Excel导入结果夹具，并按实际三参数面板核验。六岗位原生HTTP逐页核对来源、已排与阻断任务、原件权限及30次完整导出；每次获准读取分别核对资源1,154条、人机1,771条、物料联立/策略对照各2,030条来源。权限沿用原系统：六岗位可读资源试排，管理员/分析/计划岗位可读人机与物料联立及对照。

沿用0.19.0公开Excel回放库的独立副本，主库232,200条事实、初始化Excel、原编号与458份原件保持不变。本版没有新增业务输入或迁移；完整回归结果见`demo/validation.json`。纯JS与HTTP不能证明实际浏览器布局、键盘、手机或下载操作已通过，这些仍待验收。
