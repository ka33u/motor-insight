# 固化温度曲线与装炉批次

入口：平台左侧“固化温度曲线”（`#thermal-curing`）。用途是找到需要核对的炉次、装炉批次和采样区段。这里的业务记录、程序、通道、温度和时长条件均为合成演练，不是企业批准工艺。

## 使用顺序

1. 按状态、独立资源位、配置、曲线起点日期或炉次/批次/工单编号缩小范围。顶部数量与清单采用相同范围，分页不改变总量。
2. 打开炉次，核对实际程序版本、装载位置、批次、报工、工单和路线。工单订单分配提供订单行线索；没有逐件装炉订单资料时不能断言一一对应。
3. 查看每个规范通道的完整曲线、最长支持连续保温区间、采样缺口和超温点。绿色带是声明保温范围，虚线是全过程温度上限。无效采样与超过允许间隔的区段不连线。
4. 点击温度点，或聚焦后按回车/空格，查看该采样的 Excel 工作表、行号和当前修订；原始采样表独立分页。管理员可按已有原件权限下载来源文件。
5. 查看全局核对来源，核查筛选外炉次的资源重叠或规范歧义。CSV/JSON 输出完整所选炉次和原始采集输入，同时明确列出全局核对来源；不把筛选外炉次算进当前结果。

## 计算解释

演练声明炉温保温范围145至155℃（含边界），相邻采样间隔最多5分钟，至少45分钟连续保温，全过程温度不超过170℃。这些数值是自编假设，不能用于真实制造判断。

相邻两点同时满足有效℃、时间递增、均处于声明保温范围且间隔符合条件时，该区间支持保温时长估计。缺测、不可信、错单位或过长间隔中断支持区间。取最长连续区间，不把两段25分钟合并为连续50分钟；首尾不外推。升温、降温低于保温下限不自动算超限，全过程上限单独核对。

使用实际程序和版本、工单配置及路线选择唯一规范；过期、重复、缺通道或整个曲线区间不受规范覆盖时不能判为条件达到。装炉对应必须与已有报工的对象、工单、设备、资源位及声明起止一致，装载数量不得超过批次、报工投入和资源位容量。同资源位重叠在全体当前炉次上核对，随后才筛选展示。

| 状态 | 含义 |
|---|---|
| 所列曲线条件达到 | 装炉与条件核对无待补项，完整采样支持所列连续时长且未超过绝对上限 |
| 所列条件未达到 | 完整依据下，支持的连续保温不足或有效点超过全过程温度上限 |
| 采样依据不完整 | 缺装载、通道、边界、有效点或采样间隔/声明数量不完整 |
| 关系或条件待核对 | 单位、时间/序号、配方版本、装炉对应、容量或资源重叠等有疑点 |
| 采集未闭合 | 曲线终点或完整声明尚未登记；不表示现场此时仍在固化 |
| 截止外登记 | 炉次起点或采集登记超过固定合成业务截止 |
| 已作废 | 保留原采集，不进入条件达到数量 |

若多个问题并存，主状态依次优先作废、截止外、关系待核对、未闭合、依据不完整、条件未达到；全部问题仍保留。状态不能替代问题明细。

业务截止为2026-10-01 18:00上海工厂墙钟。日期筛选使用曲线起点，采样时间、登记时间、规范有效区间分别核对，失效起点不包含在有效范围内。半成品件数不合计成整机台数，也不跨独立演练案例汇总为真实产量。

## 读取与验证

六个演示岗位均可读取本专题，不返回引用档案里的价格或小时成本。API 使用 POST 的 JSON 正文承载范围，避免身份筛选写进 URL。当前结果凭据有效10分钟，绑定账号状态、全部当前核对事实、来源修订、计算代码及完整范围；明细、来源和导出发生变化时要求重读。来源页明确包含全局核对所需的筛选外资料，不能据此假定全部都在当前结果范围中。

正常导入前后的核对包括原有230,802条事实、149个旧契约、457份原件、52个模型与21个专题、首件和投产结果，以及已发布交付指标。新目录通过42份有效原始Excel重放到不存在的新数据库，保留43份原始工作簿，避免依赖作者的本机业务库。

测试覆盖34种独立情形，包括正常、含边界、恰好45分钟、超温、短保温、断点、缺测、缺通道、错单位、重复时间/序号、缺号、部分采集、缺起止、未知/过期/歧义规范、额外通道、批次错配、数量越界、缺装载、截止外、作废、未闭合和资源重叠。HTTP 检查覆盖六岗位、CSRF、完整分页、来源行、同范围导出及旧事实不变。纯 JavaScript 检查针对生成的曲线标记与路由，不等于实际浏览器验收。

真实设备导出、时钟同步、传感器校准、温场及工件芯温、材料固化机理、正式工艺评审和质量放行仍需企业确认。浏览器、手机、实际点击下载和现场业务流程尚未验收。
