# 基线 BOM 假设试排

0.21.0 新增独立入口：订单与 BOM 基线 → 基线 BOM 假设试排，地址 `#order-baselines?view=trial&study=OB-261001-008`。原基线核对和当前 BOM 试排计算保持不变。

这是“按声明的冻结用料集合，当前共享物料、设备和人员能否共同安排”的条件试算。所有业务输入仍来自正常导入的模拟 Excel，沿用第40份基线工作簿及原有人机/供给输入；本版不增加工作簿、数据库表或业务事实。

## 定义与范围

需求粒度是**批次 × 冻结快照行**，原 BOM 编号、版本、工单和订单映射保留。不同工单的同一产品可以有不同冻结版本、单耗、损耗、步长或用料集合，不能先压缩成产品级唯一 BOM。同一工单在一份基线中的快照字段不得互相矛盾。

每行独立计算：`ceil(安排台数 × 单耗 × (1+损耗) / 步长) × 步长`。数量使用 Decimal，输出为十进制字符串。共享池按物料和单位分开；不把 kg、件或 g 相加，也不隐式换算。

整案只建立一次物料、设备和人员容量。沿用原人机路线、窗口、资格和单容量条件；物料 FIFO，在绑定工序首个成功安排的任务准备开始时预留整批需求。没有共同窗口不预留；某批次后续任务未排完时，其已发生的模拟预留保留。算法尾部追加、不回填，不证明最优，供给是假设而非正式库存承诺。

## 哪些情况暂停

- 快照摘要、计数、版本链、时间或订单/工单/批次映射不能自洽。
- 当前订单头或业务身份缺失、订单状态不是支持的开放状态，数量或分配范围已改变。
- 工单不是未开工，截止时点已有装配、报工，工单跨订单分配，或安排与登记发货超过订单/工单/分配范围。
- 截止前已有生产领料，或关联流水类型、时间、数量方向、来源单号无法解释。退料及净额为零不等于从未领料，不自动扣料或退回库存。
- 冻结物料缺档案、编号身份冲突、单位不同，执行路线与保留的人机任务不符，供给资料或人机资料无效。

来源读取完整的相关工单流水人口，包含截止后的登记；未来登记不算截至时点已领料，但其增删仍会使旧来源凭据失效。无登记不证明现场实际未开工、未领料。

当前 BOM 集合、版本、单耗等变化被保留为差异，不覆盖冻结数值。当前原 BOM 行缺失时，可以在冻结身份、现有物料和执行路线明确的条件下试算；不把这解释为历史集合已被核实。**`history_verified` 始终为 false**。来源摘要只证明声明自洽，不证明文件当时存在、历史用料完整或已经签批。

## BI 怎么读

1. 先读顶部假设边界、截止和硬门槛；暂停时没有零缺料、零延迟或已完成的假数字。
2. 看原基线订单覆盖。示例订单135台、本方案安排50台、尚未覆盖85台；这不是本次加工完成后的交付承诺。
3. 在同一派序下对照当前 BOM 与冻结 BOM。需求差是冻结减当前，同物料同单位分别算；仅双方可计算才有数量差，仅双方完整排入才有批次完成时间差。
4. 看全部批次，再切设备/人员甘特与任务，或冻结用料、共享余额、供给批次和 FIFO 预留流水。清单筛选不改变整案汇总。
5. 从任务追到冻结快照行、原 BOM、触发任务和整案 Excel 来源。字段差异用业务字段逐行呈现，不让使用者阅读内部 JSON。

既有客户承诺日期、内部目标与加工完成含义不混用。不包含质量放行、运输或签收，不生成整单完工或 OTIF。

## 可核验案例

| 案例 | 结果与边界 |
|---|---|
| OB-261001-001 | 两种派序分别与同策略原试排核对；相同用料的完成时间差均为0，6批50台完整安排 |
| OB-261001-003 | due下5批完整、1批未排完；未排批次没有完成时点 |
| OB-261001-004 | 人机窗口受限，198任务均未排入；属于可计算的受阻结果，不是资料暂停 |
| OB-261001-008 | 首行6台 × 8.073 kg × 1.035，按0.001 kg向上取整为50.134 kg；当前需求55.704 kg，差−5.570 kg。此旧单耗为自编假设，非真实历史发布 |
| OB-261001-009 | 冻结g、现物料及供给kg，暂停，不自动转成“没有影响” |
| OB-261001-005/006/007/010 | 分别覆盖内容变更未重核、行数不完整、映射错误和版本链不连续 |

独立回归另有同产品两工单：2台用B1，需2.8 kg；3台用B2，需3.5 kg。共享6 kg时先派批次完整预留，另一批缺0.3 kg且预留为0；共享6.3 kg时两批顺序占用同一设备和人员，合计预留6.3 kg。两种派序改变哪批先完成，供给和人机不重复使用。这是算法测试夹具，不是新增导入业务事实。

## 来源、权限与导出

仅管理员、分析、运营三岗位可读；保留六岗位拒绝和授权回归。POST正文中的凭据绑定账号、策略、基线、当前资料、完整来源、规则和结果，默认10分钟。资料或角色变化后需重新读取。

完整 JSON/CSV 保存冻结输入、原基线核对、原人机/供给输入、当前 BOM 结果、冻结结果、关联领料登记和全部来源。新白名单还保留实际校验所需的员工有效标识与显示名、技能原登记、路线依赖/必需标识及资源生效日/位置；不导出工资、采购成本、订单单价、联系方式或凭据。离线回归仅凭导出 JSON、零数据库查询重跑全部计算链，结果一致。CSV由服务端生成最终BOM字节，审计摘要对应实际返回内容，客户端不二次添加。
