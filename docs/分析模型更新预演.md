# 分析模型更新预演

在“自由分析”中打开已保存模型，调整度量、条件或显示方式，选择“保存模型 → 更新当前模型”。系统先展示新旧定义、试算和依赖，填写变更依据并明确确认后才更新模型版本。

## 核对顺序

1. 选择本次试算的产品族、客户及日期范围。范围仅用于预演，不加入模型固定条件，也不自动继承某个专题的临时范围。两侧各自的模型条件始终保留。
2. 核对名称、共享状态、数据集及定义差异。原定义和候选定义使用同一份当前资料独立计算，并分别标出粒度、日期角色、单位、样本和缺失情况。日期选择对象范围，不还原历史数据库。
3. 看整范围摘要。比率使用全部已筛选来源的分子、分母；平均数不平均分组平均值。分组预览最多15组，摘要不受预览条数影响。缺来源、空范围、缺字段、零分母与不支持条件明确区分；试算暂停不会被填成零。
4. 看对象范围变化。同一数据集按完整主键列共同、新增纳入和移除对象，来源每页25条；跨数据集不按相同文本编号配对。新增纳入不是业务新增，移除不是客户或订单流失。
5. 看可访问专题及本人保存的视角、口径卡、页面和快照。个人视角检查候选条件兼容性及日期角色变化；其他人的私有对象与数量不列，外部引用不作完整性承诺。
6. 填写至少5字的变更依据并确认。模型增加版本，另存新旧定义、核对范围及摘要；已有专题引用新模型，个人绑定须重新核对，历史快照保持原有定义和数值。

“模型更新记录”分页查看新流程产生的定义变更。启用前版本不补造；记录不保存当时试算数字，不提供自动回退。更新模型、发布正式指标、批准生产事项是不同流程。候选定义合法但某个试算范围暂停时仍可在明确核对后保存；保存本身不证明该模型在所有范围可计算。

## 版本与权限

- 管理员可更新可访问模型；分析员只可更新本人模型。生产、质量、财务及只读岗位不能通过该入口改模型。
- 预演凭据有效10分钟，绑定当前账号权限、定义、事实修订、试算范围和可列依赖；变化后必须重新预演。模型旧版本、未知参数和未确认请求被拒绝。
- 相同申请编号和完整请求重试不会重复增加版本。已保存后重试返回当时应用的版本及当前模型；不同内容不能复用编号。
- 更新模型、追加定义记录与审计在同一事务完成。记录经正常模型服务不可覆盖并校验摘要；这不是数据库管理员不可篡改的电子签章。
- 源记录身份、摘要及导入行在查看来源时核对；本功能没有逐次扫描所有原始文件字节，原件下载仍使用已有权限和归档服务。

## 接口与升级

已有数据库先备份，再执行 `python manage.py migrate --noinput`，最后重启服务。迁移 `0022_analysis_model_change` 只新增定义变更表及 Django 元数据，不改52个已有模型、业务事实或私人配置。

| 接口 | 用途 |
|---|---|
| `POST /api/models/{id}/change-preview` | 提交版本、候选定义、试算范围与可选显式联动，取得预演凭据 |
| `POST /api/models/{id}/change-evidence` | 以凭据读取原侧/候选侧的全部或集合差异来源 |
| `POST /api/models/{id}/change` | 凭据、依据、明确确认及申请编号，原子保存新版本 |
| `GET /api/models/{id}/changes?page=1` | 按当前权限读取定义历史 |

`POST /api/models` 继续用于新建；带已有模型编号的旧式更新返回409及 `model_change_preview_required`。旧自动化脚本的模型更新调用须改为预演和确认两步，不能绕过。API支持显式对象联动；当前更新对话框只提供产品族、客户及日期选择。

## 已验证与边界

0.17.0通过2,630项完整回归。隔离HTTP核对六岗位权限，以及管理员/分析员从144条同日能耗记录筛选到24条同车间记录的独立加总、Excel来源、版本保存、重试和旧视角待重核状态；这些数字来自合成Excel。全新目录从41份当前有效Excel重建230,802条事实。升级检查保留52张旧非迁移元数据表内容、149个原始定义、457份本机原件、首件复核和发布交付指标。

纯JS检查覆盖缺值与零、前导零、分子分母、对象变化按钮和不可信文本转义。浏览器实际布局与操作、手机、键盘及实际下载未验收。正式多方审批、订阅通知、通用字段依赖图、保存候选草稿和历史数值回放仍待建设。
