# 联立试排候选人机依据

0.24.0 在物料、人机联立试排中补充任务候选资料。示例入口 `#joint-schedule?study=MP-261002-006`：该方案没有共同连续可用窗口，详情仍可核查候选人机，不因“最终未选中”而只看到空编号。

## 读取路径

从任务明细或甘特任务进入，先看原任务状态、缺料和首个阻断，再看“候选人机与窗口依据”：

1. 候选设备保留原候选号、资源位、工序、并行容量、处理台数及批量上限。批量符合与本次选中分列；首次或跨族换型假设不替代任务实际试排换型时间。
2. 候选人员保留候选号、工号、资格及技能编号、登记状态和日期、资格假设与原计算有效交集。登记到期日包含当天，时刻窗口右侧不包含；无有效交集不补零时间。
3. 分别展开设备和人员的原输入窗口、不可用段及依据。按完整资源位或工号关联，未选中的候选仍保留。窗口未扣不可用段、其他任务占用，未裁剪到试排范围；不能据此直接宣布有空闲时段。
4. 点击直接前序或原算法传播的首个阻断任务，沿同一方案、策略及凭据继续核查。当前任务自身不重复生成跳转。阻断传播不等于已经查明的现场根因。
5. 详情直接来源补齐所有使用的候选、技能、人员、窗口和不可用段。共享竞争仍需查看全方案来源、甘特及完整导出；来源索引不授予原件下载权限。

## 计算与权限边界

这是对同一次试排输入和结果的只读展开。批量符合使用原算法同一设备上限条件，资格交集直接使用原人员计算结果；没有重算可开工时间、推荐替换设备人员、重排其他批次、释放预留、修改模型或生成正式派工。

读取权限沿用管理员、分析和计划岗位。响应按字段白名单构造，不输出人员工资、成本或任意原始附加字段；来源和原件权限仍分开。展示定义摘要绑定原签名凭据，升级后旧凭据需要“重新读取”；读取中定义或权限变化则拒绝返回旧内容。

所有候选原输入已在原完整JSON导出中；把结果、资源输入、人员输入及公开资源引用交给同版候选展开函数，可零数据库查询复原相同内容。本版不改变完整导出的原排程及预留结果格式。

## 验证与未完成项

19项新增服务端测试核对批量条件、资格失效、空窗口、跨任务隔离、白名单、原结果不变、来源、角色及凭据变化；13组纯JS核对中文表、空值、转义、完整编号链接与弹窗竞态。

六岗位隔离HTTP覆盖10个方案×两策略；三种获准岗位各核对15份任务详情及首阻断跳转、2,030条全方案来源和4次完整导出。已排、缺料和无共同窗口三例在每个获准岗位下均从导出复原，9次检查的数据库查询数为0。查询计数前清空调试日志，避免日志上限掩盖差值。

沿用0.19.0公开Excel回放库的副本；主库232,200条事实、原计算算法、初始化Excel与458份原件保持不变。无新增业务输入和迁移。完整回归见`demo/validation.json`；浏览器布局、手机、键盘、实际下载以及真实工厂使用仍未验收。
