# 换型准备与交期核对

“物料人机联立试排”的两策略对照页增加准备构成和交期结果。使用原Excel输入及原试排输出，不增加或重排任务。`MP-261016-001`可看到准备360→240分钟，同时整案晚结束6.6分钟、晚交增加1批；两个结果要一起阅读。

## 定义与范围

| 项目 | 定义 |
|---|---|
| 事件粒度 | 策略 × 原设备资源位 × 已排任务，保留原任务、批次、换型族及选中候选号 |
| 首次上机 | 同一设备没有前一已排任务；初始族未登记，按候选准备分钟计算 |
| 跨族换型 | 当前批次族与同设备前一已排任务所属批次族不同 |
| 同族延续 | 两任务族相同，准备为0；仍有加工占用 |
| 准备时长 | 原候选声明分钟向上取整至整秒，再核对原准备开始至加工开始时长；汇总按秒累加后显示分钟 |
| 事件次数 | 首次上机或跨族任务的数量，含明确声明0分钟的事件，不把0分钟等同于没有切换 |
| 准备差值 | 优先级策略减交期策略；只有两列已排任务集合相同且非空才计算。相同数量但任务不同仍不可比较 |
| 整案结束 | 全部任务排入时取最大完成时点；未排完保留空值。两列都排完才比较结束时差 |
| 已完成批次中晚交 | 完成晚于该批内部应完成时点的批次数。未排完另列，不推断其最终晚交状态；两列都全排入才计算晚交批次数差值 |
| 时间差 | 本地业务墙钟时间，包含休息和夜间，与准备/加工占用分钟含义不同 |

设备与人员是同一安排的两种视角，准备时间只累加一次。两列有相同但不完整的已排任务集合时，可以比较这一集合的准备量，仍不能形成整案结束或晚交差值。均未排入时准备观测量为0，差值不计算；资料暂停不显示准备量0。

## 阅读和操作

两条准备构成条共用从0开始的刻度，分别给出首次上机、跨族与总准备分钟，并显示任务覆盖、事件次数。右侧并列整案结束、已完成批次中的晚交和未排完批次。差值保持固定方向，不按颜色推荐策略。

“换型准备核对”明细页默认看跨族事件，可按原设备、策略和事件类别取交集，30行翻页。设备展开表保留两列原准备构成和各自任务数；点设备筛选对应事件。点当前任务或同设备前一任务，进入现有两列任务详情，核对当前/前一换型族、选中候选声明分钟和原结果。

切换页签保留事件范围，重新读取两列重置为默认。重置按钮可查看全部已排任务。筛选变化取消过期的弹窗响应。所有局部筛选只影响明细，整案准备摘要、共同Excel来源和完整两列导出始终保持全方案。

## 来源、导出与权限

批次族来自`试排模拟批次`，声明准备分钟来自`试排候选资源`，时序来自原试排结果。来源沿用原文件摘要、工作表、行号和记录版本。角色访问与原对照页一致；展示只使用许可字段，不展开工资、成本或额外档案属性。

`joint-setup-reading-v1`定义摘要绑定原对照凭据。输入、账号或定义改变后旧凭据失效，需要重新读取。JSON包含两列完整输入和输出、新准备核对；CSV增加定义、汇总、策略、设备和事件分区。仅凭导出中的两列结果与资源输入，就能使用同版`app/joint_setup.py`零数据库查询重建，保留0值与空值区别。

核对会检查任务/批次完整范围、源身份、候选、时点及分钟、设备和人员重叠、逐批次完成与晚交、原摘要。失配暂停本次读取，不静默给出节省量。前一事件按同设备原时序读取，不是排程优化建议；没有具体型号转换矩阵、模具约束、收益估算、现场效率或正式派工。

浏览器布局、手机、键盘与实际下载仍未验收。规则/接口、纯JS状态与原生HTTP检查不代替视觉或现场使用验收。
