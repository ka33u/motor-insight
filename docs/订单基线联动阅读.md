# 订单基线联动阅读

0.22.0 完善“订单与 BOM 基线”的日常核对路径。入口 `#order-baselines?study=OB-261001-008`，沿用既有正常 Excel 导入和原计算结果；不增加业务记录、数据表或计算口径。

## 面向计划岗位的阅读顺序

1. 先看完整基线状态、订单覆盖和客户日期。本案例始终保留135台订单、50台安排、85台未覆盖；批次排完不代表整单交付。
2. 点选订单行，或选择“阅读订单行”。只显示该原订单行关联的批次、冻结用料和字段差异；即使两个订单同产品也不会互相混入。
3. 点选批次继续查看用料。“相符/待核对”只筛选用料表，不隐藏订单或工单字段差异；每页40行，可读完全部行。
4. “查看批次依据”重新核对当前凭据，以中文业务表展示订单、工单、分配、BOM与路线版本、原承诺、基线现承诺、内部目标、加工完成、复制单耗/损耗/步长、当前试排绑定以及直接 Excel 来源。
5. 可恢复完整阅读范围，也可进入独立的冻结 BOM 假设试排。切换基线、版本或派序会重新读取，明细选择不跨基线保存。

顶部汇总及订单覆盖表始终是**完整基线**。明细范围标签列出当前映射数/全基线映射数、当前用料数/全基线用料数，不另造局部KPI。三个日期和加工完成含义分别保留，客户日期按原规则使用当日结束，不转成OTIF。

## 来源和导出范围

- “查看批次依据”是当前批次直接来源，其用料按映射号对应；提示其他批次可能竞争共享物料及人机。
- “全方案来源”始终读取整案来源，分页范围与标签一致。
- “全基线CSV/完整假设JSON”始终导出整案，不因局部阅读选择而悄悄漏掉输入。需要局部导出时须另行建设带同范围依据的功能，本版没有冒用全基线导出。
- 阅读选择只保存在当前页面内存，不写入URL、数据库、模型、专题或业务系统。原件仍按原权限读取。

## 已修复的问题

旧页把两参数形式的表格调用传给三参数面板，导致HTML出现在标题说明里。本版按现有面板契约把正文放回正确位置，覆盖问题、警告、订单覆盖、批次、用料、差异和版本区；没有改变其他页面的全局面板语义。

旧批次详情及差异中的原始JSON改为业务表。暂停、缺失、未完成及零分母不补成零；数值0仍如实保留。切换订单清除不兼容批次，恢复全部可重见全部54行。来源/详情采用同一弹窗请求序号，后发请求、关闭弹窗、改变阅读范围或离开页面会使旧响应失效；导出防重复点击。

## 核验与边界

24组新增纯JS数据、字符串及异步状态检查，使用两份来自正常导入模拟Excel的结果夹具。按真实三参数面板契约核对正文，检查订单×批次关联、同产品跨订单隔离、分页、All恢复、单位差异、原始字段转义、来源/导出范围及旧响应丢弃。既有26组冻结试排检查继续保留。

原计算与接口文件、主库及模拟初始化输入保持不变。完整Django回归及六岗位隔离HTTP检查另记录于`demo/validation.json`；HTTP核对原结果、全部来源与文件字节，不能证明浏览器布局或交互正确。

浏览器、手机、实际键盘操作与浏览器下载仍未验收。所有业务数值均为合成演练，不是现场实绩；本页不做生产批准、正式派工或客户交付承诺。
