# 投产条件核对

入口：`#launch-review`。本功能把现有订单与BOM基线、固定物料人机试排、原工装台账和新登记资料关联。它回答“所列试排任务的开工依据是否满足”，不签发开工许可，也不自动调整计划。

第41份自编Excel包含10个独立案例、6类输入、4,270行。基础方案对应6个试排批次、50台、198个任务和66个批次工序；每个批次工序都须明确工装、工艺文件、质量条件。原订单135台中仍有85台未被本方案覆盖。

## 核对规则

| 条件 | 核对内容 |
|---|---|
| 范围完整性 | 声明行数、内容摘要、批次工序覆盖和三类条件完整。缺行、重复、跨方案或摘要错误暂停整方案，不能当作“不需要” |
| 工装 | 配套配置、工序、要求版本、设备绑定、登记状态和时效；原台账状态、到期日、累计次数及维护阈值 |
| 工装竞争 | 同一物理工具跨任务独占；借用、停用窗口排除；完整换型与加工不能重叠 |
| 文件 | 指定登记必须匹配配置、工序、版本，状态已发布且有效窗口覆盖完整任务；不自动回退旧文件 |
| 质量条件 | 指定登记对应工单、工序及版本；受限、待核对、缺登记与所列条件满足分别显示 |
| 前序影响 | 依赖工序未满足时向后续传播；保留原试排时点，并显示前序任务编号 |

核对使用固定模拟资料截止2026-10-01 18:00。登记晚于截止则资料不足，不把未来登记当成已确认事实。有效时间区间左闭右开，完整任务终点可等于失效起点；工装台账到期日保守按当日00:00失效。工具台账不是校准证书或历史有效性的证明。

工装预算按任务开始时间、编号顺序分配，候选按工具和配套编号选择首个满足登记条件的对象。每台使用次数×任务数量逐份号累计，同一台不能按整个批次重复计次。其他文件或质量条件受阻时，仍保留已分配工装的保守占用与次数；未找到工装的需求保持未满足，不计成零。此方法不搜索全局最优分配，不作维修后的寿命重置或延时重排。

## BI的呈现与阅读

先看整方案任务数、满足/阻断/资料不足，以及整个批次全部满足的数量，再看具体订单、工单和任务条件矩阵。按批次或结果筛选不会改变全方案竞争、工装预算和顶部汇总；CSV与JSON明确导出整个方案。每页最多50个任务，全部任务均可翻页查看。

点击任务可以查看各条件原因、候选工具为何被排除以及直接Excel依据；跨任务竞争和前序原因需要结合全部来源、工装占用及完整JSON。来源索引显示文件、工作表、行号和当前记录版本，原件读取仍遵守岗位权限。

基础案例的198个任务中，10个满足所列登记条件，182个受直接或前序阻断，6个资料不足。原工装台账存在超过维护阈值的工具，转子铸铝工序尚未登记配套工具；这些缺口没有被新模拟文件覆盖或改写。其他案例分别展示文件版本差异、质量限制、工装借用、缺文件、漏条件、文件失效、BOM基线待核对、缺人员窗口和摘要错误。

“登记条件满足”不意味着现场可以启动。新文件与质量条件均为自编登记，文件号不证明原件审阅完成；质量条件不是首件实测、工序检验批准、整机放行或实际生产许可。正式文件审批、工装借还事件、现场质量闭环和授权派工仍需后续建设。

## 权限、导出与验证

管理员、分析、生产三岗位可读取；由于依赖人员试排，质量、财务和只读岗位不能读取该完整方案或新增原始数据集。查询凭据绑定账号、规则、完整来源和结果，有效期10分钟；资料或权限变化须重新读取。导出记录审计和文件摘要，不输出读取凭据或财务价格字段。

本版使用规则/API测试、正常Excel导入、独立数量与占用验算、全新公开目录回放、六岗位隔离HTTP以及纯JS呈现检查。浏览器实际布局、点击下载与手机交互仍待验收，不能用HTTP或字符串检查代替。
