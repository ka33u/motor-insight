# 两策略批次获料对照

0.28.0 在原“两种派序对照”的“物料与预留差异”页增加按批次获料的并列视图。它回答：总物料预留量没有变化时，究竟是哪些批次增加或减少获配？数量相同时，是否只是供给批次、触发任务或时点改变？

## 阅读顺序

1. 先看完整批次对照，再进入物料页核对全方案物料总量。
2. “批次获料对照”默认选择有数量变化的物料；没有数量变化时优先显示流水变化，否则从第一种物料开始。可切换原物料号与原单位。
3. 同一行并列两策略的已预留、未预留、预留需求行数及原批次安排状态。两列条形共用该物料所有批次中的最大需求量作为满宽，保留精确数值；筛选和翻页不重设刻度。
4. 点击该批次的“核对关联任务”，进入**该批次＋该物料工序**的任务清单，并显示全部匹配任务。手动批次及“只看变化”选择取交集；“重置为全部任务”恢复全方案任务。
5. 点击任务打开原两列整批需求及预留依据。顶部共同来源、完整两列CSV/JSON仍覆盖全方案。

物料页可以仅看获配量或流水有变化的批次，并按20行分页。物料选择与任务范围在页内切换时保留，重新读取或切换方案后重置。切换阅读范围时取消未完成的旧任务弹窗，避免旧响应覆盖当前选择。

## 数量与状态口径

| 内容 | 定义 |
|---|---|
| 粒度 | 原物料号＋原单位＋原批次号；同一整批需求只计一次 |
| 本物料所需量 | 该批次、该物料全部整批需求之和；不按工序份号再乘一次 |
| 已预留 / 未预留 | 原试排需求与分配流水核对后分别求和；两者之和等于所需量 |
| 获配差值 | 优先级策略已预留 − 应完成时间策略已预留；保留十进制精确值 |
| 增加 / 减少获配 | 差值为正 / 负的批次分别计数；增加量 − 减少量 = 物料总预留差值 |
| 仅流水变化 | 获配量相同，但原需求/供给配对、预留数量、触发任务或时点不同；其他物料导致的全局流水序号移动不单独计为变化 |
| 批次状态 | 保留每列原排程结果；未排完无完成时间，不显示为0分钟 |
| 图形刻度 | 当前物料的最大单批需求量；所有批次、两列和分页共用，深色已预留、浅色未预留，空白是与最大值的差额 |

各物料涉及的批次数有交叠，不能逐物料相加。总汇总中的“数量变化批次”按批次号独立去重；不合计不同物料或单位的数量。不把预留增加表述成实际物料转移，也不把未预留直接归因为缺料。

## 已导入例子

44号合成Excel的 MP-261009-001 中，两批各6台，每批需要硅钢85.699 kg。两策略总预留均为85.699 kg，总差值为0；但B001减少85.699 kg，B002增加85.699 kg，获配对象改变。

MP-261009-002供给充足，两个批次在两策略下均获配全部需求。获配量不变时，预留触发时点仍可能随派序改变，单列为流水变化。以上均为独立未来假设，不是库存实绩或正式计划。

本物料全预留不证明所有物料齐套，也不等于批次已排完、可以开工或能够交付。先占未来物料、整批预留、不抢占和未排完不自动释放等原有计算边界继续适用。

## 来源、版本、权限与导出

新增内容放在原 `POST /api/joint-comparison/<方案>` 的 `batch_materials` 字段。保留原批次、任务、物料及流水差值；原调度器、BOM需求和物料预留算法不变。新展示定义及其依赖的逐物料核查定义纳入原签名凭据，定义变化须重新读取。

来源沿用两列共同的完整Excel行索引，任务明细沿用原凭据核验。管理员、分析和计划岗位可以读取，其他岗位不能通过导出或明细绕过限制。界面中的局部选择不会写入业务数据。

完整JSON包含全部新对照行；CSV追加“批次获料/定义、汇总、materials、rows”分区。将JSON的两列原 `result` 传入同版 `app.joint_batch_material.build(left, right)`，可零数据库查询复原该视图。暂停方案返回空行及空汇总，明确为未计算，仍保留原输入。

## 验证边界

新增规则及接口测试覆盖净变化为0的批次取舍、完整供给、部分获料、缺人、供给无需求、份号、不同单位、同数量的流水变化、共同刻度、异常账、字段白名单、凭据变更、无写入和离线复原。纯JS检查表格、数量条、精确值、转义、筛选/分页、任务交集、重置、异步旧响应和全方案导出。

在0.27.0公开Excel正常回放库的隔离副本上，经六岗位HTTP检查12个方案；全部原Excel、232,941条事实及24份原策略输出保留。本轮没有新增Excel或数据库迁移。具体检查数量见 `demo/validation.json`。浏览器布局、手机、键盘及实际浏览器下载仍未验收。
