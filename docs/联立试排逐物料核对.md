# 联立试排逐物料核对

0.26.0 在物料、人机联立试排中提供同料需求、供给和预留核查。从“物料与预留”总量表点物料号，或从任务详情中的用料、原缺料项点物料号，按同一方案、策略、物料原编码及原单位打开。

## 阅读顺序

先看同一数量刻度上的需求/供给构成，再核查相关批次、需求适用任务、供给批次和原序分配。图保留精确值与图例；宽度仅用于数量比较，不是到料时间轴。kg和件、不同物料不会混合。

点击任务可以继续看候选人机、窗口、首阻断和任务来源，并返回刚才的物料。用量按整批需求一次计量；同一路线多个份号的任务都可查询，但不会重复增加整批用量。

## 计算定义

| 内容 | 定义与限制 |
|---|---|
| 需求构成 | 所需量 = 已预留量 + 未预留量；均沿用原整批需求结果 |
| 供给构成 | 假设供给量 = 排除量 + 已预留量 + 范围内剩余 + 范围外剩余 |
| 排除量 | 隔离批次全部排除；可预留批次扣除登记的“其中不可预留量”，不能重复扣减 |
| 原总量缺口 | max(0, 所需量 − 范围内可用供给)，与原试排平衡表一致；不代表时间齐套 |
| 未预留量 | 所需量 − 已预留量；未预留可能来自人机或前序受阻，不能自动解释为物料短缺 |
| 范围内/外 | 假设可用时间严格早于试排终点才属范围内；终点及之后到料的剩余分别保留 |
| 同料批次 | 按需求对应的原批次号归集；台数和物料量分别显示，批次状态仍来自原排程 |
| 原流水序号 | 保留原算法提交分配的顺序，不按预留时刻重新排序；序号可能因其他物料而不连续 |

预留时点可能不单调：原启发式可按派序先占未来物料，后续任务不能抢占已预留数量。未排完批次的既有预留继续保留。这里不释放、调整或重新分配物料，也不替代库存实绩、领料或正式派工。

服务端使用Decimal核对原数量、需求/供给守恒及预留关联，不用JavaScript浮点数生成业务总量。未排时刻保留为空，资料暂停不提供伪造的零量视图；完整结果不一致时拒绝形成物料核查结果。

## 来源、版本与导出

读取权限沿用管理员、分析和计划岗位，原件下载权独立检查。物料详情只输出指定字段，保留所有同料需求、适用任务、供给的Excel文件/表/行及版本，不展开成本、工资或任意附加属性。

物料展示定义摘要绑定原签名凭据；输入、规则、账号或定义变化须重新读取。同一凭据用于物料和任务候选下钻；关闭、换详情或重新读取时丢弃过时响应。顶部来源、甘特、汇总和CSV/JSON导出仍是全方案范围。

完整JSON的原`result`可传入同版`app.joint_material_evidence.build(result, material_id, unit)`，零数据库查询复原同一物料核查内容。原排程、BOM需求、预留结果与导出格式未改变。
